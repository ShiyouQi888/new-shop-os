# 电商代理商系统规划方案

> 版本：v2.0  
> 日期：2026-08-24  
> 模式：零售商城 + 大礼包入会 + 月度领货权益 + 站内转卖 + 三级分销佣金

---

## 一、商业模式总览

### 1.1 核心逻辑

本系统是一套「**零售商城驱动 + 会员分销增值**」的电商体系。前台商城面向所有用户开放零售商品购买，大礼包作为特殊商品承担入会入口功能；代理商享有会员折扣、月度领货、转卖变现和三级分销佣金等增值权益。

```
                        ┌──────────────────────┐
                        │      前台零售商城       │
                        │  (所有用户可自由购买)    │
                        │  普通商品 + 大礼包商品   │
                        └──────────┬───────────┘
                                   │
                    ┌──────────────┼──────────────┐
                    ▼              ▼              ▼
              购买普通商品      购买大礼包       浏览/加购
              (享会员折扣)      (成为代理商)
                    │              │
                    │              ├── 一次性获得等值商品
                    │              ├── 获得月度领货权益（10个月）
                    │              │       ├── 领取自用
                    │              │       └── 站内转卖变现（扣20%服务费+快递费）
                    │              ├── 获得商城会员折扣
                    │              └── 获得三级推广资格
                    │                      │
                    │                      ▼
                    │              推荐新会员购买大礼包
                    │                      │
                    │                      ▼
                    │              三级分销佣金（一级/二级/三级）
                    │
                    └── 零售订单也可计入推广业绩（可选配置）
```

### 1.2 会员等级体系

| 维度 | 普通会员 | 银卡代理商 | 金卡代理商 |
|------|---------|-----------|-----------|
| **入门条件** | 免费注册 | 购买 5,800 大礼包 | 购买 9,800 大礼包 |
| **一次性商品** | — | 价值 5,800 元大礼包 | 价值 9,800 元大礼包 |
| **商城折扣** | 原价 | 9折（可配置） | 8折（可配置） |
| **月度领货额度** | — | 580 元/月（可配置） | 980 元/月（可配置） |
| **领货周期** | — | 10 个月（可配置） | 10 个月（可配置） |
| **转卖资格** | — | 有 | 有 |
| **转卖服务费** | — | 20%（可配置） | 20%（可配置） |
| **一级佣金比例** | — | 10%（可配置） | 15%（可配置） |
| **二级佣金比例** | — | 可配置（如3%） | 可配置（如5%） |
| **三级佣金比例** | — | 可配置（如1%） | 可配置（如2%） |
| **推广资格** | — | 三级分销 | 三级分销 |

> **设计说明**：
> - 佣金比例按「**被推荐人购买的礼包等级**」对应，而非推荐人自身等级。即：A 推荐 B，B 买 9800 则按 9800 的三级比例计算；B 买 5800 则按 5800 的三级比例计算。
> - 所有比例、额度、周期均在运营后台「权益规则配置」中可动态调整，无需改代码。
> - 商城折扣按会员自身等级生效，银卡全场 9 折、金卡全场 8 折（大礼包等特殊商品可排除折扣）。

### 1.3 三级分销关系链

```
A（顶级推荐人）
 │
 ├── 一级推荐 → B
 │              │
 │              └── 二级推荐（对A而言）→ C
 │                                  │
 │                                  └── 三级推荐（对A而言）→ D
 │
 └── 当 D 购买大礼包时：
     • C（D的一级推荐人）→ 一级佣金
     • B（D的二级推荐人）→ 二级佣金
     • A（D的三级推荐人）→ 三级佣金
```

**佣金计算示例**（以默认配置为例）：

| 场景 | 一级佣金 | 二级佣金 | 三级佣金 | 平台佣金支出合计 |
|------|---------|---------|---------|----------------|
| D 买 9800 | 9800×15%=1470 | 9800×5%=490 | 9800×2%=196 | 2156（22%） |
| D 买 5800 | 5800×10%=580 | 5800×3%=174 | 5800×1%=58 | 812（14%） |

> 三级比例可独立配置，建议合计不超过 30%，控制平台成本。

### 1.4 商品流转闭环

```
┌─────────────┐     采购/入库      ┌─────────────┐
│  供应商/厂家  │ ─────────────────→ │  系统总库存   │
└─────────────┘                    └──────┬──────┘
                                            │
                        ┌───────────────────┼───────────────────┐
                        ▼                   ▼                   ▼
                 零售订单发货         大礼包订单发货        领货订单发货
                        │                   │                   │
                        │                   │                   ▼
                        │                   │            代理商领货自用
                        │                   │                   │
                        │                   │                   │ 选择转卖
                        │                   │                   ▼
                        │                   │            ┌─────────────┐
                        │                   │            │  站内转卖池   │
                        │                   │            └──────┬──────┘
                        │                   │                   │ 系统匹配
                        │                   └───────────────────┘
                        │                                       │
                        └───────────────────────────────────────┘
                                        转卖商品回流，优先匹配给
                                        新大礼包订单 / 零售订单发货
```

### 2.2 技术栈建议

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 前端（商城+代理商） | Vue3 + UniApp | 一套代码编译 H5/小程序/APP，商城与代理商中心整合在同一端 |
| 前端（管理后台） | Vue3 + Element Plus | PC 端运营后台 |
| 后端 | Java Spring Boot / Node.js NestJS | 模块化单体或微服务 |
| 数据库 | MySQL 8.0 | 主库，事务型数据 |
| 缓存 | Redis | 会话、库存预占、商品详情缓存、排行榜 |
| 搜索 | Elasticsearch | 商品搜索、订单检索 |
| 对象存储 | 阿里云 OSS / 腾讯云 COS | 商品图片、凭证 |
| 消息队列 | RabbitMQ / RocketMQ | 订单异步、佣金结算、通知 |
| 定时任务 | XXL-Job / Quartz | 月度领货生成、佣金结算、转卖匹配 |
| 支付 | 微信支付 / 支付宝 | 商城购买、大礼包、佣金提现 |

## 三、前台商城 + 代理商系统（Shop + Agent Portal）

> 前台商城与代理商中心整合在同一 H5/小程序/APP 中，用户登录后根据身份展示不同入口和权益。

### 3.1 模块总览

```
前台商城 + 代理商系统
├── 【商城模块】
│   ├── 1. 商城首页
│   ├── 2. 商品分类
│   ├── 3. 商品搜索
│   ├── 4. 商品详情
│   ├── 5. 购物车
│   ├── 6. 订单结算
│   └── 7. 我的订单（零售）
│
├── 【代理商专属模块】
│   ├── 8. 代理商工作台
│   ├── 9. 月度领货
│   ├── 10. 转卖中心
```

### 3.2 商城模块详细功能

#### 3.2.1 商城首页

## 五、核心业务流程设计

### 5.1 零售商品购买流程

```
用户浏览商城 → 选择商品 → 加入购物车/立即购买
    │
    ▼
订单结算页
    │
    ├── 未登录 → 引导登录/注册
    │
    └── 已登录 → 显示会员价
            │
            ├── 普通会员 → 原价
            ├── 银卡会员 → 9折（可配置）
            └── 金卡会员 → 8折（可配置）
    │
    ▼
选择地址 → 确认优惠明细（会员折扣金额）→ 提交订单
    │
    ▼
微信/支付宝支付 → 支付成功
    │
    ▼
扣减库存 → 生成零售订单 → 通知仓库发货
    │
    ▼
仓库发货 → 物流跟踪 → 用户确认收货 → 订单完成
    │
    ▼
（可选）若开启零售订单分销佣金 → 计算三级佣金
```

### 5.2 大礼包购买与入会流程

```
用户通过推广链接/商城大礼包专区 → 浏览大礼包
    │
    ▼
选择 9800 或 5800 大礼包 → 查看权益说明
    │
    ▼
确认购买（大礼包不参与会员折扣）→ 微信/支付宝支付
    │
    ▼
支付成功 → 触发以下动作（事务一致性）：
    │
    ├── ① 创建大礼包订单（待发货）
    ├── ② 会员等级升级为对应代理商（银卡/金卡）
    ├── ③ 记录三级分销关系：
    │       - 新会员的一级推荐人 = 推广链接所属会员
    │       - 二级推荐人 = 一级推荐人的推荐人
    │       - 三级推荐人 = 二级推荐人的推荐人
    ├── ④ 生成 N 个月的月度领货权益计划（N=后台可配，默认10）
    ├── ⑤ 计算三级佣金并冻结：
    │       - 一级推荐人 = 礼包金额 × 一级比例
    │       - 二级推荐人 = 礼包金额 × 二级比例
    │       - 三级推荐人 = 礼包金额 × 三级比例
    ├── ⑥ 发送入会成功通知
    └── ⑦ 通知仓库发货大礼包商品
    │
    ▼
仓库发货 → 用户确认收货 → 售后期满（默认7天）
    │
    ▼
三级佣金解冻 → 转为可提现 → 通知各层级推荐人
```

**佣金回滚**：若大礼包订单发生退款，已结算佣金从推荐人钱包扣除；未结算佣金直接取消。

### 5.3 月度领货流程

```
每月定时任务 → 为所有有效代理商生成月度领货权益
    │
    ├── 金卡：额度 = 后台配置（默认980）
    └── 银卡：额度 = 后台配置（默认580）
    │
    ▼
发送领货通知
    │
    ▼
会员进入月度领货页面
    │
    ├── 选择①：领取商品自用
    │       → 浏览领货商品池 → 选品 → 确认领货
    │       → 扣减额度 → 生成领货订单 → 仓库发货
    │
    └── 选择②：转卖变现
            → 进入转卖流程（见5.4）
    │
    ▼
当月到期未处理 → 按后台配置规则处理（作废/顺延/自动转卖）
```

### 5.4 商品转卖与匹配流程

```
会员选择转卖 → 系统显示预估：
    商品价值 - 服务费（后台可配，默认20%）- 快递费 = 预计到账
    │
    ▼
确认转卖 → 扣减月度领货额度 → 生成转卖单（待匹配）
    │
    ▼
转卖单进入匹配池
    │
    ▼
【匹配触发】
    ├── 新大礼包订单需发货 → 优先从匹配池调拨
    ├── 零售订单需发货 → 优先从匹配池调拨
    └── 定时任务批量匹配
    │
    ▼
匹配成功 → 转卖商品发货给买家 → 转卖单完成
    │
    ▼
结算金额打入卖家钱包 → 通知卖家
    │
    ▼
超时未匹配（后台可配，默认30天）→ 按规则处理（兜底/取消/继续）
```

### 5.5 三级分销佣金流程

```
代理商 A 分享推广链接
    │
    ▼
新用户 B 通过 A 的链接注册 → B 的一级推荐人 = A
    │
    ▼
B 分享链接 → 新用户 C 注册 → C 的一级=B，二级=A
    │
    ▼
C 分享链接 → 新用户 D 注册 → D 的一级=C，二级=B，三级=A
    │
    ▼
D 购买大礼包（如 9800）
    │
    ▼
系统按后台配置的 9800 礼包三级比例计算：
    ├── C（一级）= 9800 × 15% = 1470
    ├── B（二级）= 9800 × 5% = 490
    └── A（三级）= 9800 × 2% = 196
    │
    ▼
三笔佣金同时创建，状态：待结算
    │
    ▼
D 确认收货 + 售后期满 → 三笔佣金同时解冻 → 可提现
    │
    ▼
各层级推荐人可分别申请提现
```

**关系链截断规则**：
- 若某层级推荐人账号被冻结/禁用，该层级佣金归平台所有，不向上补齐
- 若推荐关系不足三级（如新人是平台直接注册，无推荐人），则只有有推荐人的层级发放佣金

### 5.6 升级补差流程（5800 → 9800）

```
银卡会员申请升级金卡
    │
    ▼
系统计算补差 = 9800 - 5800 = 4000（金额后台可配）
    │
    ▼
已领货月数处理（后台可配策略）：
    - 策略 A：已领部分按 580 算，剩余月份升级为 980
    - 策略 B：重新计算 10 个月，需补差更多
    │
    ▼
支付补差 → 等级升级为金卡 → 权益调整
    │
    ▼
升级后，该会员后续推荐的新会员按 9800 礼包比例计算佣金
（其已产生的历史佣金不受影响）
```

## 七、财务与分润规则

### 7.1 资金流向（以金卡 9800 为例）

```
新会员支付 9800 元
    │
    ├── 平台收入：9800
    │
    ├── 支出①：三级佣金合计（默认配置 22%）
    │       ├── 一级推荐人：9800 × 15% = 1470
    │       ├── 二级推荐人：9800 × 5% = 490
    │       └── 三级推荐人：9800 × 2% = 196
    │
    ├── 支出②：大礼包商品成本（假设成本率 30%）≈ 2940
    │
    ├── 支出③：10个月领货商品成本（每月980，成本率30%）≈ 2940
    │       （若会员转卖，则平台支付转卖结算款，商品回流再利用）
    │
    └── 平台毛利 ≈ 9800 - 2156 - 2940 - 2940 = 1764（粗略）
        （转卖服务费 20% 为额外收入；零售商城利润为额外收入）
```

### 7.2 转卖场景资金流

```
会员转卖 980 元商品
    ├── 商品价值：980
    ├── 服务费（20%，后台可配）：196 → 平台收入
    ├── 快递费（后台可配）：10 → 物流公司
    └── 结算给卖家：774 → 卖家钱包

商品匹配给新大礼包/零售订单发货：
    → 平台无需额外采购，节省商品成本
```

## 八、合规风险提示与建议

> **重要**：本模式涉及「入门费 + 三级分销 + 拉人头佣金」，合规风险高于普通电商，需严格把控。

### 8.1 风险点

| 风险 | 说明 | 建议 |
|------|------|------|
| **传销界定** | 《禁止传销条例》规定：入门费+拉人头+层级计酬三要素。三级分销恰好触及层级计酬边界 | ① 严格以真实商品销售为基础，佣金来自商品利润而非入门费；② 不设团队计酬、不设级差；③ 三级是法定上限，不可再加；④ 商品必须真实交付、有价值 |
| **资金池风险** | 预收 9800/5800，需持续 10 个月供货，新增不足可能兑付困难 | 控制增长节奏，确保供应链，设立准备金 |
| **转卖变现性质** | 月度领货可转卖变现，可能被认定为「投资回报」 | 强调商品属性，转卖是「代卖服务」，不承诺转卖成功率和收益 |
| **三级分销展示** | 团队树、层级关系图可能视觉上传达传销感 | 团队页面按 Tab 列表展示，不画树状图；文案用「合作伙伴」而非「下线」 |
| **宣传合规** | 禁止「稳赚」「躺赚」「月入过万」「三级收益」等承诺性表述 | 审核所有推广素材，使用合规话术 |
| **支付合规** | 大额收款需合规通道，避免二清 | 使用持牌支付机构，资金不过平台账户直接结算 |
| **税务合规** | 三级佣金支出需代扣代缴个税 | 与财务/税务顾问确认，佣金超 800 元需代扣个税 |

### 8.2 合规设计建议

1. **协议先行**：注册时签《用户协议》，购买大礼包时签《代理商服务协议》《分销合作协议》《转卖服务协议》
2. **商品真实**：大礼包和领货商品必须真实、有价值、可交付，不得「空转」
3. **冷静期**：大礼包购买后 7 天未发货可无理由退款
4. **信息披露**：推广页明确展示佣金规则、三级比例、转卖费率，不隐瞒
5. **文案规范**：统一使用「推荐」「合作伙伴」「分享奖励」，禁用「下线」「拉人头」「团队计酬」
6. **三级封顶**：技术上硬编码最多三级，不可配置超过三级
7. **风控机制**：异常账号检测（同一 IP/设备多账号、短期内大量注册、虚假交易），自动冻结佣金
