# Shop-OS 后端接口路由与字段字典

> 文档版本：1.1
> 更新时间：2026-11-03
> 依据：`apps/server/src/app.ts`、`apps/server/src/routes/`、`apps/server/src/db/schema.ts` 与 `apps/server/src/db/index.ts`
> 本文覆盖当前 Express API v1、请求字段、主要响应字段及 PostgreSQL 持久化字段。路由和校验以代码为准；修改接口或数据库字段时应同步更新本文。

## 1. 通用约定

### 1.1 服务与路径

| 项目 | 约定 |
| --- | --- |
| API 前缀 | `/api/v1` |
| 健康检查 | `GET /api/v1/health` |
| 上传文件访问 | `/uploads/<文件名>`（静态资源，不属于 JSON API） |
| 请求体 | JSON；上传接口使用 `multipart/form-data`，字段名 `file` |
| 金额 | JSON number，单位人民币元；业务入账前按两位小数取整 |
| 时间 | `YYYY-MM-DD HH:mm:ss` 本地时间字符串；字段为空时为 `null` 或空串，依响应定义 |
| 分页 | 通常为 `page`、`pageSize`，响应 `{ list, total, page, pageSize }`；各接口可设置自己的上限 |

### 1.2 身份与权限

请求头格式：`Authorization: Bearer <token>`。管理员 token 的 `type=admin`，会员 token 的 `type=member`，两类 token 不能互换。管理接口每次请求都会从数据库读取管理员状态和角色权限；会员接口会检查会员是否被冻结。

| 标记 | 要求 |
| --- | --- |
| 公开 | 无 token；适用于商城展示、站点配置、公开帮助内容 |
| 会员 | 使用会员 token；接口根据 token 中的 `mid` 确定会员，不接受客户端指定会员 ID |
| 管理员 `权限码` | 管理员 token 且角色拥有权限码；`super_admin` 拥有全部权限 |
| 超级管理员 | 管理员 token 且角色为 `super_admin` |

主要权限码：`dashboard:view`、`product:view`、`product:edit`、`category:edit`、`gift:edit`、`banner:config`、`order:view`、`order:ship`、`order:refund`、`member:view`、`member:edit`、`relation:view`、`poster:config`、`commission:view`、`commission:config`、`withdraw:view`、`withdraw:audit`、`benefit:config`、`credit:view`、`credit:adjust`、`resell:view`、`resell:match`、`workorder:view`、`workorder:handle`、`help:manage`、`finance:view`、`system:admin`、`system:log`、`system:file`。

### 1.3 响应与错误

成功响应统一使用 `{ "code": 0, "message": "...", "data": ... }`。创建成功通常使用 HTTP 201。失败响应由错误处理中间件输出非零 `code` 和 `message`；常见 HTTP 状态为 400（校验/业务规则）、401（未登录或 token 无效）、403（无权限/账号冻结）、404（资源不存在）、409（冲突）及 500（未处理服务错误）。

### 1.4 状态值

| 对象 | 值 |
| --- | --- |
| 启停 | `0` 停用，`1` 启用 |
| 会员 | `1` 正常，`2` 冻结 |
| 订单 | `0` 待支付，`1` 待发货，`2` 待收货，`3` 已完成，`4` 已取消，`5` 退款中，`6` 已退款 |
| 订单类型 | `1` 零售，`2` 入会礼包，`3` 月度领货兑换 |
| 佣金 | `0` 待结算，`1` 可提现，`2` 已提现，`3` 已冻结，`4` 已回滚 |
| 提现 | `0` 待审核，`1` 待打款，`2` 已打款，`3` 已驳回 |
| 转卖 | `0` 待匹配，`1` 匹配中，`2` 已匹配，`3` 已完成，`4` 已取消，`5` 匹配失败 |
| 月度额度 | `0` 待使用，`1` 部分使用，`2` 已用完，`3` 已过期，`4` 已转卖 |
| 额度流水类型 | `1` 发放，`2` 使用/转卖扣减，`3` 后台调整，`4` 回补 |
| 文件类型 | `1` 图片，`2` 视频 |
| 支付类型 | `wechat` 微信，`alipay` 支付宝；模拟回调只在 `mock` 模式开放 |

## 2. API 路由目录

除特别注明外，所有路径均以 `/api/v1` 开头。请求字段为 JSON camelCase；分页接口的响应数据放在 `data` 中。`—` 表示无请求体。

| 方法 | 路径 | 身份/权限 | Query、Path 或 Body |
| --- | --- | --- | --- |
| GET | `/health` | 公开 | —；返回 `name`、`uptime` |
| POST | `/auth/login` | 公开；有登录限流 | `{ username, password }` |
| GET | `/auth/me` | 管理员 | —；返回当前管理员摘要和权限 |

## 3. PostgreSQL 数据字段字典

### 3.1 字段类型

`SERIAL` 用于自增主键，`INTEGER` 用于数量、状态和布尔值（`0/1`）；金额使用 `NUMERIC(14,2)`，比例使用 `NUMERIC(10,4)`，位置/时长等测量值使用 `DOUBLE PRECISION`；`TEXT` 用于文本、编码后的 JSON、路径和时间。可空字段在下方标注 `NULL`。JSON API 通常把下划线字段别名为 camelCase，但少数旧接口仍返回数据库原字段名，见 §2.5。

### 3.6 业务口径与安全边界

- 三级推荐关系按 `member.inviter_id → second_inviter_id → third_inviter_id` 快照保存；佣金以 `commission` 记录为结算主体。
- 佣金到期时间保存在 `settlement_due_time`，确认收货后按规则排期；读取商城/佣金接口会尝试结算到期记录。
- 提现申请时钱包资金进入 `frozen`；驳回时释放回 `balance`；打款后扣除冻结额并写 `finance_flow`。
- 转卖申请只接受服务端计算值；系统匹配/后台完成时将净额入会员钱包，完成后记录服务费收入与转卖支出；取消时回补对应额度。
- 领货兑换超出额度、需要现金补差价时，`credit_redeem_pending` 暂存额度/钱包抵扣，支付成功后才正式扣减。
- `system_config.config_value` 以文本存储，业务读取方根据 key 转换为数字、布尔或枚举；更新时不允许任意修改配置分组。
- 线上支付目前保留统一支付单结构和 mock 回调；配置页不允许切换真实支付模式，直到真实支付创建、签名、异步通知、退款和对账闭环完成。
- 上传目录 `/uploads` 以静态文件形式公开访问；管理 API 上传与元信息管理需要 `system:file`。

## 4. 维护说明

1. 新增/修改路由时同步更新 §2，并注明身份、权限、Query/Path/Body 和主要响应字段。
2. 修改 `SCHEMA_SQL` 或 `ensureColumn()` 时同步更新 §3；数据库字段应优先使用 snake_case，JSON DTO 使用 camelCase。
3. 任何价格字段必须注明销售、营销参考或成本用途；资金结算只读服务端计算结果和订单快照。
4. 可通过 `pnpm --filter @shop-os/server typecheck` 验证服务端类型；当前项目没有从这份文档自动生成 OpenAPI 的机制。
