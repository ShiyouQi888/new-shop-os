# 橙选 Shop-OS 电商代理商系统

> 零售商城 + 大礼包入会 + 月度领货权益 + 站内转卖 + 三级分销佣金 —— 一套完整可部署的电商代理商业务系统

包含运营管理后台（PC）、会员商城（H5 / 可打包 Android App）、Express + SQLite 后端服务，三端共用同一套类型定义与设计规范，开箱即可通过 Docker 部署。

## 核心功能

**会员商城（H5 / App）**
- 商品浏览、分类、搜索、购物车、下单、支付（内置模拟支付网关，预留微信/支付宝真实网关配置位）
- 会员等级折扣、入会大礼包购买、代理商身份升级
- 月度领货额度、站内转卖（发起 / 匹配 / 结算）
- 三级分销：专属邀请码、推广海报（固定 / 随机千人千面）、团队列表、佣金明细、提现
- 收货地址、收藏、浏览历史、消息通知、客服工单、帮助与规则文档

**运营管理后台（PC）**
- 数据看板（营收趋势、订单趋势、等级分布）
- 商品 / 分类 / 大礼包管理，订单管理（发货、批量发货、退款审核）
- 会员管理、分销关系、佣金规则配置、佣金记录、提现审核与打款
- 等级权益配置、月度领货规则、转卖规则、全局参数（含站点 Logo / 图标可视化配置）
- 财务总览与资金流水、客服工单处理
- 系统设置：管理员账号、基于权限点的角色管理、操作日志与登录日志、文件素材库

## 技术栈

| 层级 | 技术 |
|------|------|
| 管理后台前端 | Vue 3 + Element Plus + Vite + TypeScript |
| 商城前端 | Vue 3 + Vant 4 + Vite + TypeScript（Capacitor 打包 Android） |
| 后端服务 | Express 4 + TypeScript + Node 内置 `node:sqlite` |
| 鉴权 | JWT（管理员 / 会员两套独立 Token 体系） |
| 状态管理 | Pinia |
| 图表 | ECharts |
| 共享层 | 自研 `@shop-os/shared`（设计令牌 + 类型定义 + 工具函数 + Composables） |
| 包管理 | pnpm Workspaces（Monorepo） |
| 部署 | Docker Compose（Express 容器 + 2 个 Nginx 静态站点容器） |

## 快速开始

需要 Node.js ≥ 18、pnpm ≥ 8。

```bash
# 安装依赖
pnpm install

# 启动后端服务（http://localhost:3000）
pnpm --filter @shop-os/server dev

# 启动管理后台（http://localhost:5173）
pnpm dev:admin

# 启动商城 H5（http://localhost:5174）
pnpm dev:shop

# 构建全部（server + admin + shop）
pnpm build:all
```

后端首次启动会自动创建 SQLite 数据库文件并幂等写入种子数据（管理员账号、演示会员、商品、等级配置等），可重复启动不会重复插入。

## Docker 部署

项目已内置 Docker Compose 部署，包含三个服务：

| 服务 | 说明 | 默认端口 |
|------|------|---------|
| `server` | Express + SQLite 后端，数据持久化到 `shop_os_data` volume，上传文件持久化到 `shop_os_uploads` volume | 3000 |
| `admin` | 管理后台，Nginx 静态站点 + 反向代理 `/api` `/uploads` 到 `server` | 5173 |
| `shop` | 会员商城，Nginx 静态站点 + 反向代理 `/api` `/uploads` 到 `server` | 5176 |

```bash
# 可选：复制环境变量模板后按需修改端口、域名、JWT_SECRET
cp .env.docker.example .env

# 构建并启动
docker compose up -d --build

# 查看日志
docker compose logs -f

# 停止服务
docker compose down
```

默认访问地址：

| 服务 | 地址 |
|------|------|
| 会员商城 | http://localhost:5176 |
| 管理后台 | http://localhost:5173 |
| 后端健康检查 | http://localhost:3000/api/v1/health |

生产环境使用独立域名时，请在 `.env` 中调整 `SERVER_BASE_URL`（用于拼接上传文件的可访问地址）与 `JWT_SECRET`（务必替换为足够长的随机密钥，不要使用仓库中的默认值）。

## 环境变量

完整列表见 [`.env.docker.example`](.env.docker.example)：

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `SERVER_PORT` / `ADMIN_PORT` / `SHOP_PORT` | 宿主机映射端口 | 3000 / 5173 / 5176 |
| `SERVER_BASE_URL` | 后端对外基础地址，用于拼接上传文件 URL | `http://localhost:3000` |
| `VITE_API_BASE_URL` | 前端构建期写入的 API 前缀，使用内置 Nginx 反代时保持 `/api/v1` | `/api/v1` |
| `JWT_SECRET` | JWT 签名密钥，**生产环境必须替换** | 示例值 |
| `AUTO_SEED` | 容器启动时是否执行幂等种子初始化 | `1` |

## 业务模式

### 核心流程

1. **零售购买**：商城购物 → 会员折扣（等级可配置，如金卡 8 折 / 银卡 9 折）→ 下单支付 → 发货 → 确认收货
2. **大礼包入会**：购买大礼包 → 升级为对应等级代理商 → 自动发放当月领货额度 → 触发三级分销佣金（延迟结算）
3. **月度领货**：每月按等级发放额度 → 领取自用商品 或 发起站内转卖变现
4. **站内转卖**：扣减领货额度 → 生成转卖单 → 后台匹配零售订单 → 匹配成功后结算到账（扣服务费与快递费）
5. **三级分销佣金**：A 推荐 B → B 推荐 C → C 推荐 D，D 购买大礼包后，C（一级）/B（二级）/A（三级）按配置费率各获得一笔佣金，订单完成 N 天后自动结算（N 可配置）

### 权益规则（全部支持后台可视化配置）

- 各等级入门金额、商城折扣、月度领货额度、领货月数
- 转卖服务费率、快递费规则
- 三级分销佣金费率（按礼包等级 × 分销层级配置）
- 佣金延迟结算天数、分销总开关与分级开关
- 提现最低金额、手续费率
- 支付模式（模拟 / 真实网关配置位）
- 站点名称、客服电话、访问域名、站点 Logo / 图标

详细字段与接口见 [技术文档](docs/TECHNICAL.md)。

## 合规设计

- 三级分销为设计与代码层面的硬性上限，不支持无限层级扩展
- 文案统一使用"推荐""合作伙伴""分享奖励"，避免"下线""拉人头"等敏感表述
- 团队页面按层级 Tab 列表展示，不提供树状网络图可视化
- 大礼包商品在折扣计算中默认排除，确保代理商入门金额不受商城折扣影响

> 以上为产品设计层面的合规考虑，不构成法律意见。实际上线前，请结合所在地区对分销 / 多层次营销的具体法规要求，自行或委托专业机构进行合规审查。
